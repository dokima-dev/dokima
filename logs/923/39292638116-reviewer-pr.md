> # The ask
> 
> The required "all tests" check (full-suite.yml) can fail on test files outside the repo's tests folder.
> 
> In "affected" mode it runs `python3 -m pytest -q --testmon-nocollect $par $skip` with no path, so pytest collects from the whole repo, not from the settings' `tests.dir` (default `tests`) the way `run_all` does. On an adopter repo this collected an unrelated sandbox exercise under another folder whose imports CI does not install (`ModuleNotFoundError: No module named 'pandas'`), and the required check went red on a pull request that changed nothing there.
> 
> Fix:
> - Affected mode passes the settings' tests folder (and file pattern) to pytest, the same scope `run_all` uses, so it never collects outside it.
> - A repo whose tests folder does not exist is treated as "no tests yet" (passes, says so), like pytest's exit 5.
> - Same scope for the testmon run in agent.yml's code review (#883).
> - Tests: a repo with a stray test file outside `tests/` that fails to import still gets a green "all tests" in both modes; a failing test inside `tests/` still fails it.
