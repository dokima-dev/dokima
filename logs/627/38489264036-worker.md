**What it does.** `python3 tools/visuals.py finalize ISSUE --branch BRANCH --repo OWNER/NAME` draws the issue with the chosen branch's code and saves four files under `tests/fixtures/cards/`:
- `ISSUE.inputs.json`: the card's data, enough to draw it again offline.
- `ISSUE.card.md`: the card exactly as the branch drew it.
- `ISSUE.comments.inputs.json`: the data for the run and autopilot comments.
- `ISSUE.comments.md`: those comments as the branch drew them.

It then posts the whole drawing on the issue as one comment whose first line is a hidden marker (`<!-- visuals-fixture -->`), so the comment can be found again.

**When GitHub says no**
- If GitHub can't give the issue, nothing is saved, nothing is posted, and the command stops with one plain message naming the issue and GitHub's reason.
- If GitHub refuses the comment, the command fails with a plain message naming the issue and GitHub's reason. The fixture files are written before the post, so they stay saved in that case.

**One gap.** The example fixture on branch `fixture/card-557` has an extra `edge_case_sources` key. Today's card code no longer uses it, so the saved data file leaves it out and holds only `repo`, `issue` and `found`.
