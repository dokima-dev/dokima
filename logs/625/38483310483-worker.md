**Agent:** I added a `preview` command to `tools/visuals.py`. It posts the drawing as one comment on an issue in the private gallery repo (`dokima-dev/card-gallery`), and running it again edits that comment instead of adding a new one. The planner's tests now pass (14 of 14, including the earlier drawing tests). I didn't run the full suite; that runs at the merge gate.

How it works:
- **Posting (625.1):** it draws the issue the same way `draw` does, then posts the result to the gallery issue using the caller's own `gh` login.
- **Editing (625.2):** each comment starts with a hidden marker naming the real issue. Running it again for the same issue finds that comment and edits it. Previews of other issues and plain notes on the gallery issue are left alone.
- **Nothing written here (625.3):** it only writes to the gallery repo. If the real issue can't be read, nothing is posted and the command says why. If the gallery issue is missing, the command stops with a message naming it and GitHub's reason, and nothing falls back to this repo or the real issue.

I also changed `draw` slightly so `preview` can capture its output instead of printing it. `draw` itself behaves as before.

`work.json` is in `/tmp/dokima-out` and passes both hand-back checks. I raised nothing, and there were no open blockers to answer.
