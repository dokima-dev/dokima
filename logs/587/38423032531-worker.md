**Agent:** Autopilot no longer reads the `DOKIMA_AUTO_MERGE` repo variable: it asks GitHub to merge, and GitHub's own rules merge the pull request or hold it. The three plan tests in `tests/test_merge_approval.py` all failed before the change and pass now. They pass alongside the other merge test files (36 passed in total), and the AGENTS.md text tests pass too. I didn't run the full suite; it runs on GitHub when the pull request opens.

**How the merge works now** (`try_merge()` in `dokima/agent.py`):
- **First try:** a plain merge request. If GitHub merges it or adds it to the merge queue, that's the result.
- **Held for approval:** if GitHub holds or refuses the merge for a missing approval, autopilot first checks the branch has main's newest commit. If it does, it asks GitHub to merge directly (`--admin`), which only works where GitHub lets Dokima's app skip the approval.
- **Still refused:** if that direct merge is also refused for the missing approval, the pull request waits and the issue says `Autopilot: PR #N waits for your approval before it merges`.
- **Red check or branch behind main:** the pull request stays open and a comment tells the owner why, as before.

AGENTS.md step 6 now describes this instead of the variable.

Things for the reviewer to check:
- **"Behind main" now reads GitHub's comparison status as well as its count.** If GitHub's answer has neither, the branch now counts as up to date; before, it counted as behind. One existing test's fake GitHub returns an empty answer here, so without this change it reported a false "behind main" and broke a passing test. Real GitHub always sends both fields.
- **A missing approval is spotted by GitHub's wording.** A refusal counts as a missing approval only when its text contains "approving review". I couldn't confirm the exact text real GitHub sends when the app has no bypass. If it words it differently, the owner gets a "did not merge" comment instead of the wait line.

I raised one problem outside this issue: the setup audit (`dokima/audit.py`) still reads the old variable, so its warning about it no longer means anything.
