**Agent:** Autopilot now merges a pull request when the checks main's branch rule requires have passed, and no other check can stop it. On [#556](https://github.com/dokima-dev/dokima/issues/556) (cards show edge cases), a cancelled "sync" run stopped the merge; that can't happen now.

Both of the plan's tests now pass (2 passed); before the change they both failed. I also ran every test file that touches autopilot or merging: 464 passed.

What changed, all in `dokima/agent.py`:
- **Reading the rule:** a new `required_checks()` asks GitHub which checks main requires.
- **Judging the checks:** `unproven()` now looks only at those required checks:
  - A failed required check still stops the merge, and only that check is named in the reason.
  - A required check that is still running, or not on the commit yet, is waited for. If it never shows up within 45 minutes, the reason says it never ran.
  - If GitHub won't give the branch rule, nothing merges and the reason quotes GitHub's answer.
  - If the rule requires no checks, nothing merges.
- **Docs:** step 6 in `AGENTS.md` now says autopilot merges once the checks main requires are green.

Two limits to know about:
- It reads only the classic branch protection on main. Checks required through GitHub rulesets aren't read, so a repo protected only by rulesets will never merge on autopilot; it stops with a reason instead.
- It always reads main's rule, not the branch the pull request targets. Every Dokima pull request targets main, so this matters only for a pull request into another branch.
