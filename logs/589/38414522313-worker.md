**Agent:** I added a new workflow, `.github/workflows/fix.yml`, that opens an agent's manual fix as a pull request from Dokima's app. All four of the plan's tests pass, and the hand-back check passed.

You start it by hand on main and give it the name of the branch the agent pushed. Then it:
- **Opens as Dokima's app:** it gets the app's key and uses it to open a pull request from that branch into main. It never uses your token, so you can approve it.
- **Opens no second one:** if that branch already has an open pull request, it opens nothing new and the run still passes.
- **Fails when refused:** if GitHub refuses to open the pull request, the run fails.
- **Waits for all tests:** the pull request always goes into main, which holds it until all tests pass. The workflow never merges it or turns on auto-merge.

One small thing the plan didn't ask for: the run refuses a branch named `main`, since a fix must come from the agent's own branch.

Because this adds a workflow file, the pull request will stop for your approval before it merges.
