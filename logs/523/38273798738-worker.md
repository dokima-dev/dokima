What changed, all in `dokima/uptodate.py`:
- **Skipping (523.1):** after a merge, a pull request behind main is not updated when every "all tests" run on its head has finished and failed. If a run passed or is still going, there is none, or GitHub can't say, the pull request is updated as before.
- **One comment (523.2):** for a pull request Dokima built, its issue gets one comment saying it isn't being brought up to date. A hidden mark naming the pull request and its head stops later merges from posting it again.
- **Updating again (523.3):** each merge reads the current head, so once a new head passes its tests the pull request is updated as before.

Decisions for you:
- **Once per head, not once ever.** If someone pushes a new head and its tests fail again, the issue gets one more comment. I read "says so once" as once for each failing head.
- **Timed out counts as failed; cancelled doesn't.** A run that timed out counts as a failure, but a cancelled run doesn't, so a cancelled pull request is still updated.
