> **Planner: clarifying questions.** The planner tries to write each criterion with a source, a result (the Y in "When X, Y": something a test can observe, such as a file written, a comment posted, a number, an exit code) and a test. Each blank it cannot fill becomes one question to the owner, kind `question`. Examples for the prompt:
> - No observable result: "Make it faster": faster by how much, measured where?
> - No trigger: "Cards fold long text": on every card, or only past N lines?
> - Two readings: "Skip review for hotfixes": skip code review too, or only planning?
> - Owner's words conflict: body says sub-issues, a comment says no sub-issues. Which?
> - Cannot be tested: "Looks cleaner": manual sign-off, or is there a measurable version?
> - Bad-input result unstated: settings name an unknown model: stop, or fall back?
> - Scope edge: "All PRs": Dependabot's too?
> 
> **Reviewer: required boxes.** One per duty, every box present, entries typed, each entry a blocker unless noted. Structure guarantees the duty was addressed; the reviewer judges content.
