**What changed**
- **The setting:** `merge.auto_approve` is a known setting and is off by default. A repo that turns it on gets no warning. Owner approval stays locked for every repo.
- **Merging:** when it's on and both the code review and the merge gate pass, the pull request merges the same way autopilot merges it. A blocked review or a red check never gets that far, so nothing is merged or noted. The change is in `dokima/agent_roles.py`.
- **The note:** before merging, Dokima posts one line on the pull request. It links the code review record and names the checks that are green on the tested commit (`approval_note` in `dokima/agent_autopilot.py`).
- **Audit:** with the setting on, the audit adds one line when main requires a review (from code owners or a plain one) that Dokima's app isn't allowed to skip, and says how to fix it (`dokima/audit.py`).
- **Setup:** `python3 -m dokima.setup auto-approve OWNER/REPO` lets the app skip main's required review, keeps main's required checks, then saves the setting. If GitHub refuses, setup fails and shows GitHub's reason.

**Decisions you might want to check**
- **What `next` prints:** it now prints `merged` or `queued` instead of `stop` when a pull request merged or joined the queue by itself. The first test required this. The workflow only acts on output starting with `start `, so nothing else changes.
- **Which branch setup changes:** setup uses `branch.default` from settings, or `main` if that's empty. It doesn't ask GitHub for the default branch.
- **Small helper fix:** setup's settings writer now writes `true`/`false` as real booleans; before, they were saved as text.
