**Agent:** The plan for [#721](https://github.com/dokima-dev/dokima/issues/721) (the settings reader keeps a comment as part of a value) is ready. It passes both plan checks.

**The bug is real.** A settings line like `agent: codex  # the fast one` reads as `codex  # the fast one`, so the role names an agent that doesn't exist.

**The plan**
- **One criterion (721.1):** a comment after a value in the settings file is no longer read as part of that value.
- **Where the fix goes:** only `dokima/setup.py`.
- **New tests:** three, in `tests/test_settings_comments.py`. All three fail today for the right reason:
  - Comments after the agent, key and model lines become part of those values.
  - A quoted name with a comment after it, `"codex"  # note`, reads as `codex"  # note`.
  - A comment on a section line like `roles:  # who runs what` hides every role under it, so the role silently falls back to the default agent (Claude). This is the same bug, found while testing.
