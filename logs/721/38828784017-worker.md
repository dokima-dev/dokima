**Agent:** I fixed the bug: a comment after a value in the settings file is no longer kept as part of that value. All 3 of the plan's tests now pass. Before the change all 3 failed, as they should.

**Cause:** the settings reader kept everything after the colon on each line. So a value like `agent: codex  # the fast one` came out as `codex  # the fast one`. On a section line like `roles:  # who runs what`, the comment was read as the section's value. That hid every role under it, and they fell back to the default agent.

**Fix:** a small change to `read_settings` in `dokima/setup.py`:
- A quoted value keeps only the text inside the quotes, so a comment after the closing quote is dropped.
- An unquoted value is cut at the first `#` that has a space before it.
- I added `import re`.

**Tests:** I ran the 3 new tests plus the existing settings and agents tests: 39 passed. That was with `DOKIMA_SETTINGS` unset. With it set, 9 of the existing agents tests fail, and they fail the same way without my change. This run's machine sets `DOKIMA_SETTINGS`, and those tests read that file instead of the one they write. I didn't raise this, because it's likely only on this machine and not on GitHub.

The hand-back is in `/tmp/dokima-out/work.json` and passes both checks. Nothing was raised and no blockers were open.
