**Agent:** I fixed the failure the code reviewer found, and all 3 of the plan's tests now pass.

**The bug:** when a branch clashes with main, the planner's first round copies main's new tests onto the branch. On a re-plan, that copy looked like the branch's own work, so the plan check counted main's test as one the plan wrote, and it would reject it as a new test that already passes.

**The fix** is in the planner's branch setup step in `.github/workflows/agent.yml`. The plan check now starts from main's version of every test main changed, even when an earlier round already copied it. A test still counts as the plan's own if the branch's copy differs from main's. Main's tests are still only copied in when the branch never touched them.

**Checks I ran:**
- `pytest -q tests/test_planner_starts_with_main.py`: 3 passed. Before the fix, the second-round case on a clashing branch failed.
- The other test files that run the same setup step (`test_agent.py`, `test_clash.py`, `test_bot_identity.py`, `test_worker_pr.py`, plus the plan's file): 46 passed.
- I did not run the full suite; it runs when the pull request is checked on GitHub.

The hand-back is in `/tmp/dokima-out/work.json` and passes both checks. No reviewer blockers were open for me, and I raised nothing.

One side effect: a test the branch deleted but main changed now counts as part of the plan, because the check compares it to main's version. No test covers that case.
