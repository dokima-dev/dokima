**Agent:** A role on a Codex subscription now runs in Codex CLI, on the model the settings file names. The planner's three tests for criterion 700.1 failed before the change and all pass now. I didn't run the full suite; that runs on GitHub when the pull request merges.

The work is one new file, `dokima/agent_codex.py`, built the same way as the Kimi one:
- **Install:** puts Codex's command line on the machine with npm.
- **Start:** runs `codex exec` unattended, with the role's model and the prompt. It passes the subscription's key as `CODEX_API_KEY`.
- **Can change files:** Codex starts read-only unless told otherwise, so it is started with `--full-auto` and a worker on Codex can build.
- **Failure:** the run ends with Codex's own exit code, so a failed Codex run fails the run.
- **Stats:** turns, tokens and the transcript come from Codex's output, kept as `codex.jsonl` in the run's folder.

Two things work differently from Claude and Kimi:
- **Model shown:** Codex's output doesn't say which model ran, so the record shows the model it was started with.
- **Sign-in:** a Codex subscription can only be passed as an API key. The #696 plan mentioned writing back a stored sign-in too, but no test asks for it, so I didn't build it.

The hand-back is in `/tmp/dokima-out/work.json` and passes both checks, with no blockers raised or answered.
