**Agent:** The plan for [#853](https://github.com/dokima-dev/dokima/issues/853) (a label run drops a waiting close's work) is in `/tmp/dokima-out/plan.json`, and both checks pass. It's a single user story with no questions for you.

**The problem is real.** Adding the autopilot label by hand starts a run that waits in the same queue as close runs, and GitHub keeps only one waiting run. So a label run can replace a waiting close run. But the label run only starts planners: the code in `dokima/agent_roles.py` never does the close's work (closing a finished parent, switching a finished tree off autopilot, planning again an issue its last blocker was holding back).

**Criteria.** When a label run follows a close whose run was dropped:
- **853.1:** a parent whose last sub-issue closed is itself closed, with one comment saying its tree is done.
- **853.2:** every issue in a finished tree goes off autopilot.
- **853.3:** an issue whose plan was approved while it was blocked starts its planner again, once, with one "blockers merged" line.

**Tests.** They're in the new file `tests/test_autopilot_label_close.py`, one per criterion, each with a "should not happen" case: a parent with an open sub-issue stays open, trees still open stay on autopilot, and an issue with a blocker still open starts nothing. All 3 fail today for the right reason. As a trial, I had the label run also do the close's autopilot work (one extra call in `dokima/agent_roles.py`). The new tests and the existing label tests then all passed, and I undid that change.

**One gap the plan doesn't cover.** A parent that isn't on autopilot whose close run is dropped is still not closed by the label run. The 15-minute sweep closes it later.
