> # The ask
> 
> Commenting `/review` on an issue in the hotfix lane (labeled `hotfix`, never planned, with an open pull request) starts a reviewer run that fails at "Build the starting pack" with "No passed plan on the issue yet, or (for the worker) no plan review approving the newest plan." On the issue, `/review` is taken as a plan review, and a hotfix has no plan by design. The same `/review` posted on the pull request works.
> 
> Hit when a code review held a release until another issue merged: once it had, `/review` on the issue was the natural way to ask for a fresh review, and it failed with a message about plans the owner never asked for.
> 
> **Ask:** `/review` on a hotfix issue that has an open pull request runs code review on that pull request. If there is no pull request yet, say plainly on the issue that a hotfix has no plan to review and that code review starts once its pull request opens. A test should post `/review` on a hotfix issue with an open pull request and expect a code review run, not a plan review.

- If a hotfix issue has an open pull request, `/review` on the issue now starts a code review of that pull request.
