**Agent:** The plan for #811 (autopilot ignores a renamed label) is written to `/tmp/dokima-out/plan.json` and passes both checks.

**The problem is real.** `.github/workflows/autopilot.yml` only wakes for a label named exactly `autopilot`. The Python side already reads the label's name from the repo's settings. So a repo that renames the label in settings never starts autopilot.

**The plan is one user story with one criterion:**
- **811.1:** when a person adds the repo's renamed autopilot label to an issue, its planner starts.
- **Edge case:** after a rename, a label still called `autopilot` starts nothing. This stops a fix that just removes the name check.
- **Files the worker may change:** `.github/workflows/autopilot.yml` and `dokima/agent_roles.py`. The issue is about the workflow file itself, so changing it is allowed.

**Tests**, in `tests/test_autopilot_label.py`:
- One adds the renamed label by hand and checks the planner starts once, with one Autopilot line.
- One adds the old `autopilot` name after a rename and checks nothing starts.
- Both fail today because the feature is missing, not because they crash. The other 18 tests in those two files still pass.
- To make them possible, the shared test setup in `tests/test_autopilot_close.py` can now put a settings file on main. No existing test changed.

**A risk for the worker to watch:** if the job's name check is simply removed, the job will run for every label a person adds. Those runs join the autopilot queue, where GitHub keeps only one waiting run. A run for an unrelated label like `bug` could push out a waiting close run, and that close would never be handled. The plan has no field to tell the worker this, and no test covers it, so the code review should check for it.
