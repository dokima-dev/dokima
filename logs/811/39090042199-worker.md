**Agent:** The fix for [#811](https://github.com/dokima-dev/dokima/issues/811) (a renamed autopilot label never starts autopilot) is built, but one older test now fails and needs the planner's call.

**What changed:**
- **The autopilot workflow** (`.github/workflows/autopilot.yml`) now wakes for any label a person adds. It passes the label's name along. The plan's scope names this file.
- **The code** (`dokima/agent_roles.py`) starts the issue's planner only when that name matches the autopilot label in the repo's settings. Any other label, including a leftover `autopilot` after a rename, starts nothing on that issue.
- The check for other issues whose own label run GitHub dropped still runs on every label a person adds. Without it, an unrelated label added at the same moment could knock out a real autopilot run.

**Tests:**
- Both of the plan's tests failed before the change. All 8 tests in `tests/test_autopilot_label.py` now pass.
- Of the 93 other tests in the files that cover this workflow, one fails: `tests/test_manifest.py::test_the_guard_catches_a_label_taken_out_of_the_manifest`. It expects the workflow file to name the label `autopilot`, which is exactly what this fix removes. I did not change it; I raised it as a blocker for the planner.

The hand-back is in `/tmp/dokima-out/work.json` and passes both checks.
