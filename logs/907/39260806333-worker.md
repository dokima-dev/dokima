> # The ask
> 
> When the agent cannot log in to its model, Dokima reports the wrong failure.
> 
> Seen on an adopter repo: the model key reached the job, but the provider rejected it (`Failed to authenticate. API Error: 401 OAuth access token is invalid.`, in the run's log file). The issue then got: "The planner's run ended with its hand-back rejected by code. found no plan.json: the planner always hands back a plan...". That reads as a planner bug; the real problem is a bad or expired key, which only the owner can fix.
> 
> Fix:
> - After the agent step, if its output shows a login or key failure (401/403, invalid or expired token, failed to authenticate), end the run as "Model key rejected" instead of checking for the hand-back file.
> - The issue comment names the secret the settings use for that agent (e.g. `CLAUDE_CODE_OAUTH_TOKEN`) and says the provider refused it: make a new one and replace the repo secret. Never print any part of the key.
> - The setup audit checks the agent key once with a tiny call (when the key is present) and reports a rejected key as one line, so an owner learns at install time, not on their first issue.
> - Tests: a fake agent run that prints a 401 gives the key-rejected record, not the missing-plan one; a run with a real missing plan still gives the missing-plan one.
> ----
