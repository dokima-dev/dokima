> # The ask
> 
> v0.1.3 (#894) made the install file hand `DOKIMA_APP_KEY` and the agent keys to `entry.yml` by name. In a repo owned by a different account, the key now reaches `entry.yml`, but its inner jobs still get nothing. `entry.yml` calls its inner workflows (`uptodate.yml`, `agent.yml`, `commands.yml`, `assign.yml`, `autopilot.yml`, `board.yml`, `card.yml`, `audit.yml`) with `secrets: inherit`. When the run belongs to another account, `inherit` carries no secrets, the same as it did at the top level.
> 
> Seen on an adopter repo on `entry.yml@v0.1.3` with explicit mapping and repo secrets set:
> - `testmon / baseline` passes (it needs no secrets).
> - `uptodate / update` fails: `[@octokit/auth-app] privateKey option is required`, from `private-key: ${{ secrets.DOKIMA_APP_KEY }}`.
> 
> Fix: hand secrets over by name at every level, not only at the top.
> - Each inner workflow that reads a secret declares it under `on.workflow_call.secrets` (`DOKIMA_APP_KEY` required where it is used; agent keys optional).
> - `entry.yml` passes each one by name (`secrets: {DOKIMA_APP_KEY: "${{ secrets.DOKIMA_APP_KEY }}", ...}`) instead of `secrets: inherit`. Pass only the secrets each inner workflow declares.
> - Add a test that fails if any `uses: ./.github/workflows/...` call in `entry.yml` says `secrets: inherit`, or passes a secret its target workflow does not declare.
> - Release it as v0.1.4 (CHANGELOG heading), and point the install file at `@v0.1.4`.
> 
> Done when an adopter repo owned by another account,

**The fix:**
- The seven inner workflows that read a secret now declare it. The app key is required; the agent keys are optional. `agent.yml` and `commands.yml` declare all four keys, because the agent picks its key from the settings.
- `entry.yml` passes each inner workflow only the secrets that workflow declares, by name. No call uses `secrets: inherit` any more. `assign.yml` reads no secret, so it gets none.
- `commands.yml` calls `agent.yml` too, so that call now passes secrets by name as well.
- `CHANGELOG.md` has a v0.1.4 heading. The install file, the README and the wiki now point at `v0.1.4`.

**Tests:**
- New tests in `tests/test_secrets_by_name.py` fail if any internal call says `secrets: inherit`, or passes a secret its target doesn't declare. They also fail if a workflow reads a secret it doesn't declare, or a declared one isn't passed. They cover both `entry.yml` and nested calls.
- I made each kind of break on purpose: changing a call back to `inherit`, and removing the new declaration from `uptodate.yml`. The tests caught both.

**Three older tests changed, because they clashed with the ask:**
- A #894 test required `secrets: inherit`. It now checks that secrets are passed by name.
- The #894 test that finds which secrets a workflow reads now ignores a call's by-name list. Without that, the install file would have had to hand over the Codex and Kimi keys too.
- A #812 test in `tests/test_thin_install.py` treated a calling job as one that reads a key, and wanted it in the `keys` environment. A calling job can't set an environment, so the test now skips calling jobs. The jobs they call are still checked.

**Not checked here:** whether an adopter repo owned by another account gets a green `uptodate / update` on push. That can only be seen once v0.1.4 is released.
