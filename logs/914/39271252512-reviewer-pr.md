> # The ask
> 
> In a **private** repo, every agent run after the first one ignores the issue's branch.
> 
> The repo is checked out with `persist-credentials: false`, and the "Starting branch" step in `agent.yml` then asks `git ls-remote --exit-code --heads origin "try/issue-$N"` with no credentials. On a private repo that fails (`fatal: could not read Username for 'https://github.com'`), and the step reads the failure as "no branch yet":
> - a planner rerun starts `try/issue-N` again from the default branch, so its push is rejected (`non-fast-forward`) and the run's work is lost; the fallback merge then hits `CONFLICT (add/add)` on the plan's own test file;
> - a plan review reviews from the default branch, so it never sees the plan's tests and blocks with "no test the plan names exists on the branch";
> - a worker or code review after a plan would fail with "try/issue-N does not exist; run the planner first".
> Public repos (like this one) never hit it, because an anonymous `ls-remote` works there.
> 
> Fix:
> - Every git call to `origin` before the push step (the branch check, its fetch, the default-branch fetch) uses the run's app token, the same way the push does. Never print the token.
> - Telling "no branch" from "could not ask" apart: if the check fails for any reason other than a missing branch, the run stops with that error instead of starting over from the default branch.
> - The same run also logs `fatal: empty ident name` f
