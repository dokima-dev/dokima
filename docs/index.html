The problem

Writing code isn’t the bottleneck anymore. Trusting it is.

Review everythingand lose the speed you hired the agent for.
Skim itand ship the bugs it marked as done.

How it works

Each step runs as its own session on a fresh machine. No agent grades its own work.

  1. Plan

    The planner turns your words into acceptance criteria, each with its test, and a file scope.

  2. Plan review

    A separate reviewer grades the plan before any code is written.

    You approve with /work

  3. Work

    The worker builds it with the planner’s tests locked. A fence undoes any edit to them or to files outside scope.

  4. Code review

    A fresh reviewer, who never spoke to the worker, grades the result against the plan.

  5. Merge gate

    Every criterion’s tests run on the latest main. Only a pass reaches you for the merge.

    You approve the merge

A blocking review sends the work back by itself: to the worker for code, to the planner for a weak test.

Why GitHub-native

  • Nothing to host and no new dashboard. It runs on GitHub Actions in your repo.
  • Issues, pull requests and comments are the interface. You steer with /plan, /work and /review.
  • Every agent decision is a linked comment on the issue: a full audit trail.
  • A card at the top of each issue says where things stand, in plain English.
